# Spec 009：求职台插件（审阅草案）

## ADDED

### ADDED-1：申请记录与字段

- **要求**：一条申请对应公司 + 岗位 + 招聘批次；公司、岗位为创建时唯一必填字段。公司同名、重复岗位不强制唯一，发现疑似重复时提示并允许用户分别保留。主表合并呈现「公司与岗位」「投递情况与时间」，其他默认列为阶段、期望薪资、下一场面试、下一步。
- **验收**：只填公司与岗位即可创建未投递记录；同公司两个岗位互不覆盖；未填写的薪资或时间显示「未填写 / 待定」，不生成默认值冒充事实。

### ADDED-2：投递事实与阶段一致

- **要求**：「是否投递」由投递记录是否存在派生，不能作为另一份任意布尔值保存。已投递但历史时间未知允许保存为「已投递 · 时间未记」。首次点击「标记已投递」使用用户确认的时间，允许补录/纠错；状态切换不得隐式捏造历史投递时间。
- **要求**：开放阶段为「待投递 → 已投递 → 笔试/测评 → 面试中 → Offer → 已入职」，允许跳过不适用阶段。面试轮次属于面试记录，不将一面/二面硬编码成全局流程。终止结果包括「未通过 / 主动放弃 / 岗位关闭」，保留关闭前阶段；收藏未投递岗位也可关闭。
- **验收**：未投递记录切到面试/Offer 时，要求补录投递事实或明确选择「已投递，时间未知」；二面不能一键取消投递；纠错须同步恢复一致数据并留下原因/历史；招聘关闭不等于候选人未通过。

### ADDED-3：薪资有单位和来源

- **要求**：期望薪资保存下限、上限、币种和计价周期（日/月/年），月薪可选薪数。支持面议/未填写。招聘方给出的区间和实际 Offer 薪酬存为独立字段，不能覆盖个人期望。
- **验收**：「200–250 元/天」「12–15 千元/月 · 14 薪」「18–22 万元/年」分别正确显示。禁止负数或下限大于上限。不同币种/周期不能直接混排为同一金额排行；换算仅在用户明确假设时展示。

### ADDED-4：可编辑的多轮笔试 / 面试与不确定时间

- **要求**：一个岗位可有多个面试/测评节点，包含轮次、类型、时间、时间精度、预计/已确认、形式/地点、联系人、准备事项、结果/复盘。未定时刻可仅记录预计日期或日期范围；不得补成零点作为正式预约。
- **要求**：表格的安排时间可直接点击编辑；空值提供「添加安排」。详情「笔试 / 面试」中，每条安排通过右键/更多菜单编辑，可新增、改类型、自由填写轮次名称、修改日期和时刻、取消或标记完成。完成一轮不等于通过该轮；只有用户显式选择时才同步岗位当前阶段。
- **要求**：主表显示最早的未完成、未取消面试；时间已过但未更新结果显示「待补结果」，不把它显示成下一场预约。预计节点明确标记「预计」，取消节点不进入近期已确认面试计数。改期后保留旧时间与操作记录。
- **验收**：一面完成后主表显示二面；取消或改期后计数同步更新；只有预计日期的记录不进入准确时刻提醒；已取消面试不会继续提示。

### ADDED-5：下一步与日期边界

- **要求**：独立记录下一步行动与跟进时间；无回复不自动判失败。提醒只提示需要用户处理的投递截止、面试或跟进事项。准确时刻以 UTC RFC3339 存储、本地时区显示；日期精度和原始时区必须保留。
- **验收**：本地今日/逾期语义复用 `context_service::local_today_range`；跨 UTC 日期正确。终止或归档记录停止未来跟进提示。插件关闭/应用退出不宣称能发送系统通知；重新进入页面重新计算待处理事项。

### ADDED-6：表格操作与详情

- **要求**：支持搜索公司/岗位、按阶段/招聘批次/城市/岗位性质/工作形式筛选、按投递时间/最近变更/面试时间排序。期望薪资排序限定同币种同周期。默认每页 50 条；首列固定，其他列可隐藏，列选择与密度作为 UI 偏好保存。点击行的非交互区域或公司/岗位打开详情；右键菜单提供查看详情、编辑投递信息、笔试/面试安排等操作，行与卡片不单列编辑按钮。点击状态、安排或菜单不误触行导航；右键自身不打开详情。
- **要求**：详情以「概览 / 笔试与面试 / 动态」组织内容；顶部「更多」与右键共用菜单，安排逐条提供更多菜单。详情和编辑器撑满应用右侧可用高度，上下边缘与宿主内容区域对齐，不按内容高度悬浮；长内容在面板内滚动，操作底栏固定。关闭未保存表单需选择继续编辑或放弃。状态变更和安排修改进入时间线。归档可恢复；V1 默认不提供不可恢复的物理删除。
- **验收**：表格与详情读取同一记录版本；切换详情不丢掉表格搜索/筛选/滚动位置。空状态、新建必填错误、保存中、保存失败/重试、无结果均有明确展示。提交成功前不显示「已保存」；冲突时不覆盖外部新版本。

### ADDED-7：视觉与无障碍

- **要求**：复用宿主语义主题与字体，默认舒适行高 64–68px，紧凑模式 50–54px；表头克制，减少竖向格线。状态颜色同时配文字：待投递灰、已投递蓝、流程中紫、Offer/入职绿、终止灰/红；橙色只用于即将到期/待确认。
- **要求**：支持浅色/深色，键盘能操作表单、状态和详情关闭。右键菜单可通过 Shift+F10/菜单键和详情更多按钮打开；支持方向键、Escape、点击外部关闭及窗口边界避让。输入区域保留原生编辑菜单。抽屉有可访问名称、焦点管理和 Escape 关闭；未保存编辑先提示保留/放弃。小窗口保留关键列和表格横向滚动，不缩小中文字到不可读。桌面/窄窗口均验证面板顶部、底部和保存按钮位置。
- **验收**：正式宿主至少在 1280px 和 1024px 宽度检查，另检 736px 及 360px 的回流；两种主题无文字裁切和错误遮挡。不能只凭 TS 编译通过宣称视觉验收。

### ADDED-8：Core、CLI 与插件一致

- **要求**：求职状态、薪资校验、下一场面试、统计及所有修改规则实现于 Rust Core；SQL 仅在 dashboard-storage；UI 通过受权限约束的 Plugin API 调用。记录写入与 activity log 同事务，提交后调用 `snapshot::refresh`。
- **要求**：CLI 提供创建/列表/详情/更新/标记投递/阶段变更/面试/归档恢复等对应能力，支持 JSON 信封与现有错误语义。所有写入携带记录 revision；可重试新增/变更使用 operation_id，重试不重复产生记录。
- **验收**：GUI 与 CLI 操作同一数据；actor 由可信入口确定；CLI 修改后页面刷新可见；未声明求职能力的插件访问被拒绝。停用插件保留求职数据，启用后可继续查看。

### ADDED-9：今天求职事项卡片（推荐纳入 V1）

- **要求**：在宿主 TodayCard 扩展位置提供独立「求职事项」卡片，与求职台读相同 Core 数据。分组为过期待补记录、未来 7 天已确认笔试/面试、计划今日投递/临近截止、今天或逾期的下一步、预计待确认安排；正式版每组显示有限条数并提供查看全部。
- **要求**：保留现有 Today 的问候/快速捕捉/统计、年度热力、双列今日任务和重要日/笔记/项目右栏。求职卡接入现有内容之后的插件格位，size=lg 当前占 6/12 列；不得将其宣传为已有的右栏插槽。行的编辑从右键菜单进入。
- **要求**：仅收藏且没有计划/截止日期的待投递记录保留在求职台和汇总数量中，不每日生成待办。预计安排不能混入已确认时刻计数；关闭/归档岗位停止未来提醒。
- **验收**：修改轮次/时间后主表、详情、今天同步；取消后近期列表移除；登记投递后计划投递区移除；补录结果不会从「无回复」推导失败。
- **验收**：可在卡片直接复用详情抽屉。导航至完整求职台若需新增 API，仅允许打开本插件声明的 View；当前 SDK 没有可直接调用的该方法。

### ADDED-10：用户选择的行动与任务关联（独立实施切片）

- **要求**：每个下一步行动有稳定 action_id，用户主动选择「加入任务」；同一行动最多一个有效任务关联。任务为一次性，标题/计划日期与行动共用来源或单向投影，禁止各自维护两份可互相覆盖的数据。
- **要求**：任务完成/撤销只同步该行动的完成状态，不自动写入投递事实、招聘阶段或招聘结果。岗位/安排变更不批量创建任务；被取消、来源移除或岗位终止的未完成任务停止提醒，不伪装成已完成，保留历史。已完成行动后的新下一步获得新 action_id。
- **要求**：修改行动名称/日期更新同一关联任务；未来计划的关联任务在任务页可见，进入今日的日期过滤与逾期顺延由 Core 投影控制，不能直接依赖现有 Once 每日适用规则。记录、关联、任务及活动记录需有一致事务与幂等语义。
- **要求**：关联任务由宿主 `TodayTaskCard` / `TaskCard` 渲染，保留现有拖拽、布局、卡片样式与打卡交互。一次性任务完成后按宿主规则自动归档，今天保留当日完成记录；撤销恢复行动与任务。关联来源可跳回申请，标题/日期编辑必须走同一 Core 来源更新；不出现插件维护的第二份任务清单。
- **验收**：重复点击/请求重试仅一个任务；GUI 和 CLI 完成/撤销一致；完成准备材料后岗位仍可为面试中；改期后无旧时间残留；取消关联不删除岗位，关闭插件保留数据。
- **验收**：该能力需要新增受限 Core/SDK 接口与来源、日期契约。正式接线完成前不得把演示按钮描述为已连接真实宿主任务。

## MODIFIED

- 拟扩展 SDK / Rust capability 允许列表与路由，提供 `job.read` / `job.write`（名称草案）及求职方法。当前 SDK 不支持，不能直接在现有 manifest 声明后当作可用。
- 拟新增数据库迁移（当前 V8，下一个可用版本实施时核验），不修改历史迁移；新增 CLI 输出需要升 `meta.schema_version`，并记录消费者迁移说明。
- 兼容地扩展插件 API 时评估 v2 是否可保留，并提升最低宿主版本；若必须改既有插件契约，再独立确定协议版本，不能将数据库、CLI 与插件三个版本机械绑定。
- 拟扩展本插件视图导航，以及受限的行动 → 一次性任务关联接口。日期和任务完成投影涉及 Core/Today/CLI 的跨层改动，不能只在 WebView 订阅 `task.completed` 后修改状态。
- 拟增加宿主托管全高侧栏的 UI 契约，使从插件卡片打开的详情不受卡片滚动/变换限制；限定 owner、显示层级、焦点和卸载清理。当前 SDK 提供 React，不提供 ReactDOM/Portal 或托管面板方法，正式实现前冻结接口。

## REMOVED

无。

## 非本变更范围

- 自动投递、模拟网站登录、读取邮箱、抓取招聘网站、账号/云同步。
- 退出应用仍定时响铃、系统通知、外部日历同步。
- 通用电子表格公式、任意自定义关系数据库、复杂自定义流程。
- 首版 JSON/CSV/Excel 导入导出、按招聘状态批量自动创建任务和退出应用后的系统通知。用户选择的行动关联任务单独切片验收，不用当前每日任务 API 代替带日期的一次性行动。
