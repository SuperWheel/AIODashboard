# Change Proposal 009：求职台插件

> 状态：提案（2026-09-08）。正式插件及领域功能尚未实施。独立「求职台·试用」UI 已按用户选择导入新版桌面程序，见[试用 Plan](../../../docs/plans/2026-09-08-job-tracker-ui-trial.md)。spec / design / tasks 仍为正式功能草案。

## Why

求职记录分散在备忘录、招聘网站和聊天里，容易忘记是否投递、投了哪个岗位、下一轮何时进行，以及何时需要跟进。希望在 AIODashboard 中用一张易维护、好看的表格管理整个求职周期。

## What I Want

插件名称建议「求职台」，ID 建议 `com.leeyl.job-tracker`。

1. 表格作为主入口，一条记录对应一次「公司 + 岗位 + 招聘批次」申请。同公司不同岗位、不同批次分别记录。
2. 公司和岗位必填；投递情况、投递时间、当前阶段、期望薪资、下一场面试、下一步行动是默认显示信息。可先收藏，随后补充。
3. 点击整行或公司/岗位展开右侧全高详情；编辑放入右键菜单，列表与卡片不单列「编辑」按钮。详情顶部「更多」提供同一菜单，支持键盘与没有鼠标右键的环境。详情承载招聘链接、城市、工作形式、岗位性质、招聘渠道、联系人、备注、面试与进度历史。
4. 状态在表格中快速修改；笔试与面试都有独立可编辑安排，支持类型、轮次名称、日期、时刻、预计/已确认/已完成/取消，以及地点、准备/结果备注；投递与安排历史保留。
5. 主表支持搜索、筛选、排序、列显隐、收藏优先和归档。顶部只显示总记录、已投递、未来 7 天已确认面试、待决定 Offer 等少量有用信息。
6. 沿用现有暖纸白 / 深夜工作台双主题、翡翠绿主色、系统中文字体。浅色细分隔线、宽松行距、少量状态色；信息密集时可切紧凑密度。
7. 用户主动点击时记录投递或进度变化；本插件不代表用户执行招聘网站投递。
8. 推荐采用「今天求职事项卡片 + 按需关联一次性任务」：近期笔试/面试、计划投递和待跟进自动进入求职卡片；具体下一步由用户主动选择加入任务。完成任务同步行动完成，不自动认定投递成功、面试通过或收到 Offer。该联动方式目前为审阅建议。

## What I Know

- 2026-09-08 实际核对 `docs/PLUGIN_API.md`、`packages/plugin-sdk/src/index.ts`、`Sidebar.tsx` 与 `styles.css`：当前 SDK 支持 View / TodayCard / Command / Settings 和插件 KV，尚无求职实体、求职查询/写入 API。
- 当前 Rust Core 有 `Recurrence::Once`，语义是每日适用直至完成；Task / CreateTaskInput 没有普通截止时刻字段，插件 `core.createTask(title,target?)` 也未暴露 once 或计划日期。不能直接承诺它能生成按预约日期显示的任务。
- `TodayView` 已渲染 `extraCards`，SDK 支持 `registerTodayCard`；今日卡片参数没有 onNav。卡片可直接复用岗位详情抽屉，跳转完整求职页需补受限的本插件视图导航能力。
- 现场核对本机软件与当前组件：Today 是 12 列总控台，插件卡片位于既有热力图/今日任务及右栏之后；任务页是原生双列卡片，包含热力图、混排/分区及归档。求职插件接入这些位置，不另建替代宿主页。全高详情应由宿主托管覆盖层，避免被卡片高度、滚动或 transform 限制；当前 SDK 没有这项托管契约。
- 项目架构要求领域业务由 Rust Core 实现，SQL 仅在 storage，业务变更记录 activity 并刷新 snapshot。因此推荐「求职领域能力 + 可启停的求职 UI 插件」，不能把全部求职规则写进 JS 和 KV 后当作完成。
- 现有插件协议为 v2、CLI schema 为 6、数据库 V8。正式扩展需要新增迁移、SDK / capability / CLI 契约；具体版本在实施前复核，不能占用并行任务已使用的版本号。
- 应用退出后插件与 cron 停止。第一版的提醒是打开应用可见的面试/跟进信息；系统通知、退出后提醒另行设计。
- 界面稿的公司、岗位、薪资与时间全部为虚构演示数据，不构成招聘信息或真实求职进度。

## What I Don't Know

这些是供用户调整的产品默认值，不阻塞本轮设计：

- 默认同时适配实习和正式岗位；可后续选择是否以秋招、实习或社招为主要入口。
- 默认以手动录入为主；Excel/CSV 导入与日历订阅进入后续版本，避免首版的导入映射和提醒依赖扩张。
- 首版采用固定阶段并允许跳过流程；自定义阶段与复杂招聘漏斗统计延后。

## 交付与开发分期

- **本轮设计**：字段、交互与视觉方案；可操作的演示界面；[需求规格](spec.md)、[技术与界面设计](design.md)、[实施及 TDD 清单](tasks.md)。
- **V1 建议范围**：核心表格、可编辑资料、投递/状态历史、多轮笔试面试、下一步、归档/恢复、CLI 与插件接线，并加入「今天」求职事项卡片。
- **V1 后续独立切片**：用户选择的下一步与一次性任务关联，先补齐来源、计划日期、完成/撤销和去重契约，再开放该功能；交互稿目前仅演示此建议。
- **后续**：受控 JSON/CSV 导出与恢复、带预览/去重的导入、日历视图和 Offer 对比。自动投递、邮件读取、网站抓取、AI 自动写入不包含在本方案首版中。

## 本轮结果

- 已完成设计稿与静态交互预览；正式领域实现、数据库迁移和真实任务联动尚未开始。另行完成的内存 UI 试用版不改变正式功能的实施状态。
- 2026-09-08 审阅修订：旧稿笔试/面试只有展示，且仅公司名可打开详情，入口不够明显。现补上整行打开、明确编辑按钮、完整安排编辑、未保存保护，以及「求职台 / 今天 / 任务」同源演示。所有内容仍为内存数据，刷新重置。
- 2026-09-08 第二次审阅修订：按用户意见将列表编辑移入右键菜单，详情与编辑改为右侧全高，保存操作固定底部。现场查看实际桌面首页和任务页后，重做宿主布局示意：概览、年度热力、右栏、双列今日任务及后置求职插件卡；关联任务沿用原生卡片结构，一次性行动完成当天留在今天，任务页归入已归档。仍未安装正式插件或接通真实数据。
- 本提案按仓库 Spec 流程保留为待审阅；不能把本轮设计完成等同于插件功能完成。
- 2026-09-08 软件试用：用户明确选择演示数据版本，独立 `com.leeyl.job-tracker-trial` 已打包、导入并启用，只申请 View/TodayCard。原生软件中验证右键编辑、资料/轮次/日期时刻修改、全高详情、Today 共享试用状态、双主题和卸载重载；已有任务与打卡数据逐条核对不变。正式任务关联、持久保存、CLI 和托管覆盖层仍待本 Spec 实施。
