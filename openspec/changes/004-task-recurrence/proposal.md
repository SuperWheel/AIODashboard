# 提案：任务循环规则（每日 / 每周 / 每月 / 每年 / 每周指定日 / 一次性）

> 状态：已完成（2026-08-31 实施完毕，check.sh 全绿；三项语义决策见下）
> 级别：Spec（schema 变更 + AI 协议变更）

## Why

当前任务模型只有一种隐式循环：**每日适用**。卡片样式（day/week/month/year）只是统计展示口径，不决定"哪天需要打卡"。用户需要真正的循环语义：

- 每周三健身、每周一三五晨跑——非适用日不应出现在 Today、不应可打卡；
- 每月 1 号记账、每年纪念日回顾；
- 一次性事项（交报告、买机票）——完成即结束，不应第二天又出现在 Today。

## What

1. 新增领域概念 **Recurrence（循环规则）**，与卡片样式正交：样式管"怎么看统计"，循环管"哪天适用"。规则种类：`daily / weekly(weekday 集合) / monthly / yearly / once`。
2. 规则**存放在目标区间行上**（`task_target_periods.recurrence`，SCHEMA_V4 加列）：改规则 = 闭合旧区间、明天起新区间，历史口径不回写——与目标修改同一套区间机制。
3. 适用性判定统一为：活动区间覆盖 ∧ 目标区间覆盖 ∧ **规则命中当日**。不适用日：不进 Today、打卡被拒、热力图/统计记 `not_applicable`（不打断连续天数）。
4. **一次性任务语义**（用户决策）：
   - 未完成自动顺延——等价于"每日适用"，直到完成；
   - 完成打卡达标后**自动归档**（写 `task.archive` activity，历史保留）；
   - 期间行为与普通任务一致（可减、可撤，撤销后任务仍归档态，恢复即可继续）。
5. **错位日 clamp**（用户决策）：每月 31 号遇 30 天月份 → 当月最后一天；每年 2/29 遇平年 → 2/28。
6. 任务墙（TasksView）数据源从"今日适用任务"改为"全部启用任务的当日视图"——否则每周任务在非适用日会从任务页整卡消失；Today 视图维持只显示今日适用。
7. 协议 v3：`Task` JSON 增 `recurrence` 字段（当日生效规则）；CLI `task create/update` 增 `--recurrence`、`--weekdays`；`meta.schema_version` 2→3。

## 已确认的决策

| 决策点 | 结论 |
|---|---|
| 一次性未完成 | 自动顺延到完成（每日适用直到完成） |
| 一次性完成后 | 打卡达标即自动归档 |
| 每月/每年错位日 | clamp 到当月最后一天 |

## Unknowns（实施中澄清）

- 撤销已完成的一次性任务：补偿照写、任务保持归档态（用户可手动恢复）——不做自动"复活"。
- 插件桥 `createTask(title, target?)` v1 不暴露 recurrence（默认 daily），后续按需扩——PLUGIN_API 无破坏性变更。
- 编辑器中循环字段与目标一样受 `dayLoaded` 守卫（归档任务不改循环）。
